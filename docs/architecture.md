# osu-paint 架构

## 用途与范围

将 `#` / `.` 像素帧或本地视频编译为 osu!lazer mania 音符与 BPM/SV 控制点，在指定时间窗口近似静止展示，再快速进出场。应用可写 1–18 列，桌面端与 CLI 共用生成逻辑。配套皮肤包含 1–18K 配置，默认比例为 3072×1920 对应的 16:10；目标原版 lazer 的 >10K 转换限制见 [皮肤说明](skin.md)。

## 模块与依赖

| 模块 | 职责 | 边界 |
| --- | --- | --- |
| `osu_paint.py` | 解析文本、编译帧、积分位置、编码 `.osu`、导出与 CLI | 核心只用标准库；CLI 视频分支按需导入视频模块 |
| `osu_paint_video.py` | 参数解析、FFmpeg 抽帧与提取 Ogg、刷新窗口安排 | 调用核心编译器；使用 `imageio-ffmpeg` 定位 FFmpeg |
| `osu_paint_audio.py` | 桌面音乐播放、定位与设备生命周期 | 按需加载 pygame / mutagen；不参与谱面编译 |
| `osu_paint_desktop.py` | Tk 编辑、项目保存与打开、预览、异步导入与导出 | 调用以上模块；主线程管理控件与项目状态 |
| `osu-paint.pyw` | 无终端窗口的桌面入口 | 仅启动桌面端 |
| `osu_paint_skin.py` | 生成各比例的皮肤配置、PNG 与 `.osk` | 只用标准库；由导出与构建脚本共用 |
| `tools/build_skin.py` | 重建根目录交付皮肤，可指定行数 | 调用皮肤模块；默认 24 行 |

## 数据流与时间模型

1. `parse_frames` 产生同尺寸的字符串行数组；`---` 分帧。编辑项目可含空白帧，普通图案导出要求每帧有亮格；视频允许黑场，但整段必须有音符。
2. `compile_frames` 验证均分 / 自由时间窗口、滚速与长条开关，生成帧窗口、`Point(time, beat_length, sv)` 和音符数组。目标固定为 lazer，不接受客户端选择。
3. `Timeline` 对分段速度积分，并反求给定位置对应的时间。legacy 音符按底边锚定，H 行底边为 `(row + 1) / H`，贴图向上延伸 `1 / H`。先扣除整幅复用画面的累计漂移，再扣约 `1 / 768` 的底部余量，让展示结束时头部时间仍在未来；顶部按屏幕裁剪，避免半格偏移。判定位置为 480，时间范围为 `11485 / scrollSpeed × 480 / 402`，漂移按 768 内部像素高度报告。返回计划是导出与预览的共同输入。
4. `encode_osu` 用列中心映射 `.osu` 的 0–512 横坐标。短音符为 type 1，长条为 type 128；红线后立即写对应绿线，防止红线重置继承速度。
5. `write_output` 写 mania 谱面、音频、报告、预览和五种屏幕比例的 `.osk`，音符高度为 `480 / H`，列宽为 `480 × 屏幕比例 / 列数`。`.osz` 只包含 mania 谱面和音频；皮肤需单独导入。刷新率排帧项目另写播放说明。

lazer 使用小数时间与自身参考 BPM / 滚速模型。滚速仍是用户参数，与游戏设置一致；行数只决定音符高度，不决定游戏的时间到位置换算。长条从连续亮格的底部行起头、顶部行结束，不跨空格或不同画面。相邻相同画面可在漂移预算内共用音符。

视频按时间戳采样而非编码帧编号，支持可变帧率。自动排帧按实际频率与向上取整的分频数直接推导各边界，不提高请求 FPS；在相邻预定刷新之间分散切帧位置，降低未知显示相位连续采到过渡的风险，保留名义刷新点两侧边距。各次微调小于一个刷新周期，不累计舍入，保留请求行数。画面与 Ogg 共用开始时间，保持源音画延迟；播放器无需相位输入。请求参数、实际参数与对齐元数据仍保存于项目和报告，界面不展示内部转换说明。

## 项目、线程与副作用

桌面 JSON v1 保存画布、逐帧时间、模式与设置；v2 增加视频元数据及 Base64 Ogg，可脱离原视频继续编辑与导出。新项目不保存客户端选择或手动相位；旧项目的客户端字段、`game_fps` / `frame_fps` / `refresh_phase_ms` 被忽略，保留画面、时间、滚速与音轨后按 lazer 重编译。缺少长条字段时采用 false。TXT 不保存音轨与设置；`report.json` 是编译报告，不是可打开的项目。

导入与选帧预览在后台执行，通过取消事件终止 FFmpeg，通过队列交回结果；Tk 主线程只在成功后替换项目。导出立即重新编译并抓取计划和音轨，后台写文件，编辑不会改变正在导出的快照。音乐预览跟随音频时钟，音轨结束后画面继续播放。

编译和参数解析尽量保持纯函数；文件写入集中于导出、项目保存和独立皮肤构建，媒体子进程集中于视频模块。更改相关参数或画布尺寸后，桌面端移除已失效的刷新对齐标记。

## 验证与兼容边界

`tests/` 覆盖纯编译、实际 `.osu` 重新解析积分、Node 执行 HTML 绘制、Tk 编辑与快照、合成媒体的真实 FFmpeg 解码、Ogg 播放及皮肤包资源。测试使用合成输入，不依赖个人视频或联网。

桌面与 HTML 预览按默认 16:10 比例绘制连续几何位置，黑块高度覆盖每行，宽度铺满，长条全黑；不模拟判定、Miss 淡出、双舞台或显示刷新。刷新窗口验证使用指定频率与相位，不代表实机已经锁相。皮肤与原版客户端限制见 [皮肤说明](skin.md)；时间策略见 [刷新约束](research/render-phase-constraints.md)。

## 文件管理

Git 管理源码、文档、回归测试、示例、构建脚本和五个 `pixel-film*.osk`。皮肤包是特意保留的交付文件，必须可从脚本复现。`.build-env/` 是本地构建环境；`build/` 与 `__pycache__/` 是可清理缓存；`dist/` 保存可直接运行的 EXE；`output/` 与根目录 `.osz` 是本地导出，不进入版本库。

历史研究记录中的 `build/`、`output/` 路径是当次诊断位置，清理缓存后可能不存在。保留研究结论与版本依据；缓存是否仍在不代表功能是否支持。清理范围由用户确认，项目 JSON 与音轨不能仅凭目录名称判为冗余。
