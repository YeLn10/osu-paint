# stable 换帧内部白缝：原生变换与固定底边

日期：2026-10-09。继续处理 16×12、15 FPS、60 Hz 下“一堆白线闪过”的反馈。基线为 `40b5f70`。上一轮排帧降低了部分固定相位的重复命中，但没有改变画面之间的白色间距。

## 复现与证据范围

目标仍为本机 stable，EXE SHA-256 为 `3adc2d001aacced5f92ba8ae24121980d5e23f5653f37d14cf4765bca1abd9f9`。重新核对哈希，与 [时间证据](stable-timing.md) 和 [皮肤证据](stable-skin-evidence.md) 一致。所有输入均为合成图案；未提交游戏代码或个人媒体，未修改游戏配置。

先在上一轮未提交的回归上重放 `HEAD` 中的核心和皮肤模块：白缝断言失败，首个失败的间隙约 0.15628 个皮肤坐标单位；皮肤遮挡断言也失败。当前实现通过相同回归。没有回滚工作区来制造基线，旧源码只在测试进程中加载。

独立检查不只积分控制点，还重放目标客户端的 MovementY 创建规则：从音符时刻向前回溯、裁剪至顶部、在底部按图片高度结束、头尾及身体偏移、整数时间端点、float32 纵坐标。`tests/fixtures/stable-movement.json` 保留基线的 9 条原生反射变换，测试逐段核对时间、标记与坐标。反射仅调用移动创建与皮肤解析方法，没有调用游戏入口或 GPU。

核心症状是：一列在相邻两幅图中均为全黑，换帧时却在新旧黑块之间出现白带。原行程为 `1 + 2/768` 个舞台高度，叠加头部的判定余量，使间距在原生变换中达到约 2 个 768 高度内部像素。改变刷新排帧无法消除这一几何间隙。

## 修改与取舍

stable 的行程改为 `max(1 - 1/480 + 1/768 + 1e-6, 1 + 1/768 - 0.5/H)`。在视频支持的 1–128 行范围内，画面间略微重叠；第二项保证超高文字画布的最后一段仍有正距离。头尾的整数时刻、行高、参考 BPM、展示窗口、音符数量和音轨不因此改变。额外检查实际静置到清场开始时的漂移，避免延长静置越过既有预算。

仅缩短行程会在底边留下旧画面，所以 stable 皮肤增加 1 个皮肤坐标单位高的白色 `StageBottom`。目标舞台以底部中心锚定该资源，音符所属管理器先画、底部资源所属管理器后画；宽度不拉伸。按 1–18K 分别生成实际总列宽向上取整的遮挡，低 K 仍保留每列 100 的钳制。五种比例共 90 个 stable 配置经目标原生解析器确认 `StageBottom` 映射、资源存在、`HitPosition: 480`；同时确认该调用点的资源键确实为 `StageBottom`。

代价是底部固定白边为屏幕高度的 `1/480`：1920 高时约 4 像素，比旧判定余量约增加 1.5 像素。两端的黑色头尾与身体资源完全保留；lazer 皮肤保持透明底部。Tk / HTML 同步裁剪到相同边界，但仍使用连续几何预览。

不能将本轮结果解释为所有白线均已消失：只有两个端点的长条，头部离场变换可能在同一整数毫秒内截断；头部消失而身体尚未到达底部时，会短暂露出底边。例如 12 行、3 ms 清场的回归在 2051 ms 仍露出底边，2051.125 ms 已被身体覆盖。该反例单独保留。它与贯穿屏幕内部的移动白缝不同，GPU、生命周期和实际刷新相位尚未验收，整屏扫动也仍存在。

## 对照与回归

原生对照采用 3 幅 16×12 图案：第一列全黑，其他列逐行黑白交替并随帧反转，迫使保留全部 12 个端点行。窗口为 2000–2053、2066–2120、2133–2200 ms。两版窗口与头尾时刻逐项一致，清场仍为 13 ms。

| 指标 | 基线 | 修改后 |
| --- | ---: | ---: |
| 原生头 / 尾 / 身体移动路径 | 9 | 9 |
| 2000–2150 ms，每 0.05 ms 采样 | 3000 | 3000 |
| 含内部白缝的采样点 | 438 | 0 |
| 最大内部白缝，768 高度像素 | 2.000512 | 0 |

以上只统计黑块之间的内部空白，不把固定底边或短暂底部裁剪算作内部白缝。前后路径均与独立变换模型逐段吻合。新采样脚本在输出 float32 坐标时先转 double，避免 PowerShell JSON 格式化丢失末位精度。

回归进一步覆盖 1/3/12/24/128 行、1/27/40 滚速、长条开关共 30 组原生规则模型；每 0.125 ms 检查内部连续性，在下一幅开始及其展示期间确认旧列不再可见。五种比例的底部 PNG 检查覆盖 90 个配置。名义刷新时刻的独立 `.osu` 积分、可采到两幅混合画面的反例、手动清场时长、Tk 与 Node 执行 HTML 的裁剪均保留。密集 65 帧的固定相位白带回归现在要求内部白缝为 0；原有总过渡时间与相位评分要求不放宽。

## 应用方式与来源

使用重建的 EXE 打开已有 JSON，重新导出 `.osz` 和皮肤，再导入匹配比例、实际行数的 stable `.osk` 并选中。必须同时更新谱面与皮肤；仅更新其中一项不能获得上述结果。旧 JSON 的帧时间和音轨保持，不需要重新抽视频。根目录十套交付皮肤仍为 24 行。

- 官方 [skin.ini](https://github.com/ppy/osu-wiki/blob/master/wiki/Skinning/skin.ini/en.md) 的 `StageBottom`：资源路径，宽度不自动拉伸；2026-10-09 复核。
- 官方 [mania 皮肤资源](https://github.com/ppy/osu-wiki/blob/master/wiki/Skinning/osu!mania/en.md)：底部资源及原点说明；同日复核。
- 上述哈希的原生 `StageLayout`：资源创建 L276–282、水平居中 L372–374、先音符后底部 L653–662、底边坐标 L807–814。缓存位置继承 [皮肤证据](stable-skin-evidence.md) 的 B5。
- 同版本 `HoldStyle` 的头 / 尾 / 身体移动生成及身体高度 L536–566；原生反射输出与测试 fixture 补足执行证据，不用静态代码替代 GPU 结果。
