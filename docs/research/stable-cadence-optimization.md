# stable 整数帧间隔下的连续重叠优化

日期：2026-10-09。基线为 `4fcd862`。用户确认已同时更新谱面与皮肤，剩余症状是换帧时旧图、新图重叠拖尾；选择保留 12 行，接受有限改善。

## 复现与范围

先用两幅左右分离、各行都有端点的合成图案复现。重新解析 `.osu`，按目标 stable 的 MovementY 创建和裁剪规则计算可见音符，2040–2053 ms 每 0.125 ms 采样：103 个采样点同时出现旧图、新图；在 2049 ms 断言“只有一幅图可见”失败。换帧结束后旧图已离场，所以这次主要处理有限换帧本身的暴露，不继续修改白缝皮肤。

本机 stable 的 SHA-256 再次核对为 `3adc2d001aacced5f92ba8ae24121980d5e23f5653f37d14cf4765bca1abd9f9`。模型沿用与该版本原生反射逐段比对的 `tests/fixtures/stable-movement.json`，见 [白缝记录](stable-white-seam.md) 和 [时间证据](stable-timing.md)。没有启动 GPU 验收，也没有诊断显示器响应时间。

当前编译方式中，密集 12 行仍需要 12 个独立整数端点和清场槽，共 13 ms。此次保持行数、图案、核心速度和皮肤，所以该两帧反例仍存在。优化目标是减少反复采到这些重叠画面的次数，尤其是连续命中长度。

## 机制与取舍

旧宽范围候选每 64 次重绘走完一个方向，长片段可能连续上百次命中重叠。直接加快三角折返会受到整数取整影响，超过原有 1 ms 帧间隔误差；把超出的步长简单截断也可能只覆盖部分相位，反而更差。

保留所有旧候选之后，仅在旧宽范围候选已获采纳时多编译一个候选，避免把原先干净的名义刷新改为过渡：

1. 在名义开始时间之前不到一个刷新周期的整数范围内，向较早／较晚的一端移动。
2. 下一帧开始时间必须在前一帧开始时间加 `ceil(名义周期 - 1)` 到 `floor(名义周期 + 1)` 之间。15 FPS / 60 Hz 时可用间隔为 66 或 67 ms，不需要两方向具有相同速度。
3. 根据取整后的实际提前量判断何时折返，不因一次碰到随刷新小数变化的边界而过早反向。复用同一音符组时保留相位目标。
4. 重编译后逐切帧检查实际推进晚于前两次名义刷新；仍保留至少 1 ms 展示。
5. 与当前已选方案比较：最坏总命中与最长连续命中均须严格下降，内部总过渡与音符数不增加，否则回退。

首帧、片尾、原始音轨起点、FPS 和画面像素保持不变。画面最多提前不到一个刷新周期，与旧宽候选采用相同边界；之前一次名义刷新可能已经进入过渡。每次换帧没有缩短，个别固定相位仍可能变差。最长路径由最多五次编译增至六次；无余量或旧宽候选未获采纳的路径不增加编译。
