# lazer 刷新约束与长条验证

核查日期：2026-10-01。应用只保留 lazer；旧整数游戏 FPS 适配和另一客户端的生成规则已移除。旧项目保留可编辑画面、时间和音轨后重新编译。

## 时间与屏幕位置

[DrawableManiaRuleset](https://github.com/ppy/osu/blob/master/osu.Game.Rulesets.Mania/UI/DrawableManiaRuleset.cs) 按滚速和判定位置计算可见时间范围。当前皮肤采用判定位置 480、内部高度 768，生成器使用 `R = 11485 / scrollSpeed × 480 / 402`。行数决定格子高度，滚速决定时间到位置的换算；两者不能相互替代。滚速入口保留，生成时须与游戏设置一致。

红线 beatLength 使用 lazer 合法范围 6–60000 ms，绿线倍率使用 0.01–10。极速清场移动 `S = 1 + 2 / 768` 个全屏高度，预算为 `C = ceil(S × R / (500 / 6 × 10) × 1000) / 1000` ms，滚速 27 时约 0.612 ms。两像素余量覆盖底边偏移及舍入误差，不再使用形成宽白带的旧 1.1 屏距离。显示阶段仍有微小正速度。长视频通过互异慢红线和短参考段保持参考 BPM 500 ms；输出独立积分检查包含分段 float32 舍入。

[LegacyNotePiece](https://github.com/ppy/osu/blob/master/osu.Game.Rulesets.Mania/Skinning/Legacy/LegacyNotePiece.cs) 和 [DrawableNote](https://github.com/ppy/osu/blob/master/osu.Game.Rulesets.Mania/Objects/Drawables/DrawableNote.cs) 使用底边锚点。当前生成器与预览采用底边定位，扣除复用画面的漂移及约 1 个内部像素余量，检查所有头部在展示结束时仍在未来；不再把底边错误当作格子中心。具体几何见 [皮肤说明](../skin.md)。

## 实际刷新率排帧

界面和视频命令行自动使用 `refresh_hz` 排帧，支持 60、120、165 Hz，以及小数或分数换算值，例如 `60000/1001`；初值 60 不代表检测结果。界面只保留刷新率和视频开始时间等必要输入，不提供相位或排帧开关，也不显示实际导入参数说明。令刷新周期 `T = 1000 / Hz`，取向上取整的整数分频 D，使采样帧率为 `Hz / D` 且不超过请求 FPS 和 60；不再四舍五入后增加换帧次数。小量浮点容差保证已换算 FPS 再解析时不继续降档。每次边界直接从共同开始时间与刷新序号计算，不逐帧累计取整。

切帧预算 C 必须小于 T。旧方案固定边距 `M = (T - C) / 2`，会把全部切帧锁在相同的周期位置：若实际显示恰好采到该位置，就会反复看到过渡中的空白带。现在使用保护边距 `G = min(C / 2, (T - C) / 4)`，令 `Mᵢ = G + (T - C - 2G) × frac(i × (√5 - 1) / 2)`，分散切帧而不依赖玩家校相位。第 i 个新画面到位时间为 `开始 + i × D × T - Mᵢ`，首帧仍为原开始时间；展示结束为下一帧到位减 C。名义刷新点两侧保留 G，偏移始终小于一个刷新周期，不累计到后续帧。所有时间保留小数，画布保留请求行数。后端保留无刷新率的普通采样路径作为测试负对照，不在界面提供切换。

首画面和 Ogg 都保留用户给定的开始时间，不移动音轨，并保留源音画延迟。旧项目中已保存的画面时间和音轨保持原样，忽略旧的手动相位字段。改变时间、滚速、清场、模式或尺寸后撤销失效元数据，重新导入才能重新安排。相邻相同画面在保守漂移预算内复用音符，主动空档仍清场。

刷新率和视频开始时间不能确定客户端的实际呈现相位。令实际采样时刻为 `开始 + n × T + φ`，未知的 φ 可位于一个刷新周期内。对于任何有限的切帧区间，都能选择 φ 使刷新恰好落在切帧中间；独立解析导出的 `.osu` 并积分，可同时看到离场旧列和入场新列。60、120、165 Hz 均有这一反例。因此自动排帧将切帧置于假定刷新时刻之间，但仅凭这两个输入不能保证原版 lazer 零残影或取消全部下落过程。该反例继续作为普通 mania 的验证边界。

## 连续闪动回归（2026-10-01）

固定滚速 27，以黑色面积恒定、左右列交替的 241 帧合成视频，经真实导入排帧路径生成。扫描 200 个固定显示相位、240 个内部换帧，旧固定居中方案最坏相位命中 240/240 次；当前缩短清场距离后的方案结果如下（请求 20 FPS）：

| 显示刷新率 | 最坏相位采到过渡 | 最长连续命中 |
| --- | --- | --- |
| 60 Hz | 11/240（4.58%） | 1 |
| 120 Hz | 22/240（9.17%） | 1 |
| 165 Hz | 32/240（13.33%） | 1 |
| 60000/1001 Hz | 11/240（4.58%） | 1 |

另用实际序列化 `.osu`，独立积分并保留 lazer 分段 float32 舍入，计算裁剪后黑色面积。旧 1.1 屏推进会在切帧中途暴露约 10% 的白带；仅分散相位不会消除它。现在将推进距离收紧为一屏加 2 个内部像素（一个用于原有底边偏移，另一个用于舍入余量）。在滚速 27、3 行、左右列交替的 50% 黑色面积样例中，切帧过程最低黑色面积从 44.9918% 提高到 49.8616%，极速时间从 0.671 ms 缩至 0.612 ms。

面积回归覆盖 1/3/24/128 行、滚速 1/27/40、短音符及长条的 24 种组合，每个切帧扫描 101 个时刻，同时检查进场前无提前可见音符、切帧结束时旧帧完整离场。旧视频的固定窗口（包括旧 0.671 ms 间隔）重新编译后保持原时间。原有任意相位混帧反例、两分钟小数时钟、名义刷新点完整画面、长条和首帧／音轨开始时间测试继续保留。

这是有限相位扫描与几何模型的结果，不是 GPU 或显示器实测。分散位置本身主要降低最坏相位的连续命中，并不减少所有相位平均的过渡暴露；收紧清场距离则另外缩短过渡并减轻几何白带。有些旧方案恰好干净的相位可能变差。代价是亚刷新周期的画面时序微调，以及向下换算 FPS 时可能降低流畅度。源视频自身闪白、阈值跳变、掉帧或显示器响应仍需分别验证。旧项目不自动改写保存的帧时间；缩小白带只需重新导出，采用分散排帧还需重新导入原视频。新谱面均需重新导入游戏。

交付验证：完整 130 项回归通过；桌面 EXE 已重建并核对五个内置模块与当前源码一致、FFmpeg 保留。尚未进行用户显示器上的实机频闪验收；几何结果不包含实际 Miss 淡出或 GPU 采样。

## 长条

同一画面、同一列连续亮格才合并，下方为头、上方为尾，不跨空格或不同画面。[DrawableHoldNote](https://github.com/ppy/osu/blob/master/osu.Game.Rulesets.Mania/Objects/Drawables/DrawableHoldNote.cs) 将身体连接到头尾中部，尾部贴图向上延伸；当前预览按尾底边减一行到头底边的整个跨度裁剪。头越过舞台后仍绘制可见尾部，不通过提前隐藏制造清场。

短音符及长条头、身体、尾均为不透明纯黑。[LegacyBodyPiece](https://github.com/ppy/osu/blob/master/osu.Game.Rulesets.Mania/Skinning/Legacy/LegacyBodyPiece.cs) 的颜色调暗不会把黑色变成灰色，整体 Alpha 淡出仍受客户端生命周期控制。身体改为 40×1024，绕过已安装框架对纯黑图集边缘的上传优化，避免原 40×1 贴图拉伸时混入透明边缘造成灰色。根因、框架探测和采样验证见 [皮肤说明](../skin.md)。
