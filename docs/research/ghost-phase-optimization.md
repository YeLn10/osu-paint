# 两端残影排帧优化

日期：2026-10-07。基线：`22bcfa1`。只使用合成画面与测试音轨，不读取用户项目或个人媒体。

## 复现与修复范围

已有清场压缩仍保留有限过渡。此次复现的是固定但未知的显示相位反复落入过渡区间，并非纹理灰边或游戏内 Miss 淡出：

- stable 在 60 Hz、20 FPS、24 行整列长条、64 次左右交替时，3 ms 清场固定在同一周期位置；存在相位命中全部 64 次。
- lazer 在相同刷新率及采样率下，每 128 个采样帧才改变画面，原三角形排帧恰好回到相同位置；存在相位命中全部 16 次内容变化。

`test_ghost_phase.py` 的两个入口测试先在旧实现失败（64/64、16/16），再验证新实现。另一个开发中反例说明：只计算内容变化、不计长静止画面的必要重绘，会让长静止序列的 27 次过渡全部集中。该方案未交付。

本次不更改 `osu_paint.py` 的 SV、参考 BPM、漂移预算、端点算法或皮肤。客户端目标及原来分段 float32 / 整数时间证据继续沿用；没有新的 GPU 实机结论。

## 最多一个受保护候选

1. 先按原排帧编译，获得核心确定的实际清场时长与音符重绘组；视频模块不复制端点分配或 SV 算法。
2. 候选的三角形步进按重绘组计数，包括静态画面受漂移限制而产生的重绘，不按采样编号计数。步长仍为 1/64，折返而非跳回起点。
3. lazer 保留已有保护边距。stable 从一个刷新周期中扣除实际清场和 1 ms 取整余量，在剩余范围移动，再一次性向下取整；先取整再插值会带来额外 2 ms 跳变，已避免。
4. 最坏固定相位评分：将涉及可见内容的实际内部过渡区间映射到一个刷新周期，跳过两侧均为空白的区间，处理跨周期区间，以端点扫描计算最大重叠数；不靠随机或稀疏相位采样作决策。
5. 仅当候选的最坏命中数严格减少，且音符数与内部总过渡时长均不增加时采用。无余量、无法保留至少 1 ms 的 stable 展示、或没有收益时保留原方案。既有长静止场景比候选更好时同样保留原方案。

只会额外编译一个候选，没有循环搜索或新增 UI 参数；代价是部分视频导入多一次编译。首画面仍使用输入起点（stable 向上取整），片尾时刻、源音画开始时间和请求行数保留。JSON 保存采用后的时间；打开旧 JSON 不会自动重排，因此需要重新导入视频使用本项优化。

## 对照数据

扫描 400 个均匀固定相位；计数表示一次内容变化的过渡区间是否至少包含一个刷新时刻，不是从实机录像数出的残影。lazer 案例为 2049 帧、每 128 帧左右交替，共 16 次内容变化；stable 为 65 帧逐帧交替，共 64 次变化。均为 24 行、两列、长条开启、请求 20 FPS，非整除刷新率仍按既有规则向下换算采样率。

| 客户端 | Hz | 最坏命中（旧 → 新） | 平均命中（旧 → 新） |
| --- | ---: | ---: | ---: |
| lazer | 60 | 16 → 2 | 0.6000 → 0.5875 |
| lazer | 120 | 16 → 3 | 1.1600 → 1.1750 |
| lazer | 165 | 16 → 5 | 1.6400 → 1.6075 |
| lazer | 60000/1001 | 16 → 2 | 0.6000 → 0.5875 |
| stable | 60 | 64 → 15 | 11.5200 → 11.5200 |
| stable | 120 | 64 → 45 | 23.0400 → 23.0400 |
| stable | 165 | 64 → 64（保留原方案） | 31.6800 → 31.6800 |
| stable | 60000/1001 | 64 → 20 | 11.5200 → 11.5050 |

lazer 的音符数仍为 33，总进退场窗口仍为 20.808 ms；stable 仍为 65 音符、196 ms。有限网格平均值的微小差异是相位分布及采样误差，不能当作总暴露下降。**本项优化减少最坏相位的重复命中，不降低这两例的总过渡暴露。某些原本干净的相位仍可能变差。**

长静止负对照：2048 帧不变后才切换一次，60/120/165 Hz 的原方案最坏命中为 2/4/6；不受保护的新候选会变成 3/6/9。收益检查全部拒绝这些候选，交付结果与原排帧的 `.osu` 完全相同。

## 回归与未解决项

- 独立解析 `.osu`，分别用 lazer 分段 float32 和 stable double/绿线 float32 积分；覆盖两端、短音符/长条、60/120/165/60000÷1001 Hz、小数起点、重复画面，在名义刷新时刻只见正确画面。
- 检查头尾仍为未来时间、stable 头尾仍是整数；窗口不累计漂移，音符数、清场时长、行数、首尾时间不因分散而增加或丢失。
- 使用真实 FFmpeg 合成源，比较未排帧与两端排帧的解码 PCM，确认音轨原始开始偏移不变。
- 保留有限过渡中可同时看见新旧列的反例；24 行短音符的 25 ms stable 清场超过 60 Hz 刷新周期时仍有任意相位命中的反例，不削减行数掩盖它。
- 既有灰边采样、未知相位反例、音轨保护、旧项目读写和完整回归继续运行。
