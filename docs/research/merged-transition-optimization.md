# 统一客户端与切帧优化验证

日期：2026-10-06。目标：一个编辑/导入/导出入口，保留 stable 和 lazer 各自的时间规则，再减少正常播放的过渡窗口。原相邻 stable 仓库、EXE 和用户媒体/项目不改动。

## 合并基线

合并提交 `6ddcc1e` 前后，两端各 7 个合成案例的完整 `.osu` SHA-256 一致，覆盖均分、手动时长、长条/空档、重复图案、空白、低滚速和小数窗口。统一项目读写 `target_client`，未标记默认 lazer；目标变化撤销刷新对齐，但不改帧和音轨。161 项测试通过，根目录两端各五个皮肤可重建且互不覆盖，统一 EXE 构建成功。

## stable：按实际头尾端点安排整数槽

旧算法给每行都留一个整数毫秒，即使那行没有任何短音符或长条端点。24 行整列长条因此仍用 25 ms。新算法只给不同头尾所在行分配整数槽，保留原空间距离；N 个端点行加一个清场槽共 N+1 ms。独立进场没有需要判定的端点，可用 1 ms。长条不能跨空格，空行不因时间压缩被填黑。

排帧仍保留 H+1 ms 最坏预算，不移动已有窗口或音轨，不借此擅自提高导入 FPS。共用切帧在原下一幅开始时结束，多余时长用于静置。全行短音符仍需 H+1 ms；关闭极速仍使用原手动时长。

## lazer：限制长静态组对全片参考速度的影响

旧算法先以保守参考速度复用重复帧，再由最长有内容组限制全片参考 beatLength。少数静态段会拖慢其余动态段。

首次优化保留原策略作基线，仅试一个按 4900 ms 参考预算分组的候选；后续的温和候选见文末。候选仍检查整个复用跨度（含延长静置）不超过半内部像素，并保留约 1 内部像素的判定余量。只有内部总切帧窗口减少至少 20%、画面组数与音符数分别增加不超过 10% 时采用。首尾进退场不计入收益，所以纯静态序列不会为了缩短首尾而重绘。未满足条件、非极速以及长单帧无法拆分时保留基线。

这里的负载上限是保守的生成器约束，不是客户端性能保证。额外重绘也可能改变闪屏出现的时刻，仍需实机比较。

## 2026-10-06 后续：按上下留白缩短 lazer 行程

旧实现将所有清场都按全舞台高度 S = 1 + 2/768 推进。两帧亮格都只占 24 行画布的第 6–17 行时，实际序列化积分仍为约 1.002604 屏；保持原速度只需约 0.752604 屏。新增 `test_padded_sweeps.py` 在旧实现先得到 3 处失败，再修改核心；失败命令为 `.build-env/Scripts/python.exe -m unittest discover -s tests -p test_padded_sweeps.py -v`。

依据现有底边几何推导，而非新增客户端渲染假设：旧顶部亮行为 t、新底部亮行为 b、画布 H 行，退出需要 `S - t/H`，进入需要 `S - (H-1-b)/H`；共享过渡取二者较大值。不能仅看旧画面顶部，否则新画面底部会提前进入。独立进退场分别使用自身边界。空白一侧没有音符需要约束；两侧为空时保留原行程，避免产生零长控制点。继续保留约一个内部像素的底边偏移和另一个像素的清场余量。

只在 lazer 极速模式按行程比例缩短时间，不提高既有速度上限、不改变 500–4900 ms 参考预算、复用漂移预算或 10% 负载上限。候选收益按压缩后的实际行程评估。`sweep_ms` 现在报告最大实际进退场时长，不把后续复用帧从首次进场起经过的展示时间算进去；UI 直接使用此值。保守排帧预算、原帧起止、主动空档及音轨不变；stable 和手动模式不采用留白压缩。

## 2026-10-06 后续：两端慢控制点精简与 lazer 预留间隔降速修正

基线为 `f20cfbe`。新增 `test_sweep_efficiency.py` 先在旧实现得到 4 处失败：两端 2 秒静止画面均有 40 个慢控制点；lazer 预留间隔从一倍预算增至 1.5 倍时，实际切帧从约 0.062449 增至 0.093673 ms，留白压缩后的同类样例也被拉长。命令：`.build-env/Scripts/python.exe -m unittest discover -s tests -p test_sweep_efficiency.py -v`。

### 两端共同优化

原实现每 50 ms 生成一个互异慢红线，以防它成为参考 BPM，但正常约 2 秒的参考前导并不要求分得这样密。新增核心内部精简步骤，只合并连续、SV = 0.01 且 beatLength 大于参考值的慢段；合并跨度不超过首段参考前导的一半。参考锚点、进退场和主动空场边界均保留，短前导不足以安全合并时保留原点。保留下来的慢红线仍互异，参考统计规则与末尾物件边界不变。

合并可能带来很小的积分差异，所以在建立时间线、反求音符头尾和报告漂移之前执行，不能在已编码 `.osu` 上直接删行。复用分组与参考预算仍按原慢段下界保守估算，最后再验证参考 BPM。手动模式逐字节保持原输出。

2 秒、24 行整列长条的合成样例：两端慢控制点均为 **40 → 3**；lazer 全部红线数 **45 → 8**、`.osu` UTF-8 字节数 **3097 → 954**；stable 全部红线数 **46 → 9**、字节数 **3198 → 982**。两端各有一个长条，头尾几何正确，stable 的整数物件文本不变，实际清场仍为 3 ms。

### lazer 单独优化

共用推进按标准极速时长乘留白行程比例，不再用预留间隔决定降速倍率。没有提高既有 SV = 10 上限、参考 beatLength 上限或放宽漂移/负载保护；只把多余间隔留给旧画面静置。超过两倍预算的主动空档仍独立进退场。复用候选也用同一时长公式评价收益。

120 帧、10 FPS、全高长条左右交替、预留两倍预算间隔的合成对照：最大切帧 **0.124898 → 0.062449 ms**，含首尾总过渡窗口 **14.987755 → 7.556327 ms**，音符仍为 120 个，参考 beatLength 仍为 4900 ms。stable 对照实际切帧仍为 3 ms，总过渡窗口不变，本轮不把控制点精简说成整数切帧变快。
