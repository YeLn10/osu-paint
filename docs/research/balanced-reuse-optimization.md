# 均衡静帧复用：缩短 lazer 总过渡窗口

核查日期：2026-10-07。对照版本：`51aac04`。本轮修改核心 `osu_paint.py`，stable 时间模型、皮肤、视频排帧算法及音轨逻辑均未修改。

## 从“分散命中”转向“缩短窗口”

前两轮主要把有限过渡分散到不同显示相位，并不减少总过渡暴露。本轮利用现有漂移模型：参考 beatLength 受最长复用平台限制；贪心分组留下很短的尾组时，较长的前组会限制整段谱面的清场速度。

例如，60 帧静止画面被已选方案分为 `29 + 29 + 2`，仍只用三个音符组，但最长组明显过长。改成 `20 + 20 + 20`，不增加重绘次数，即可在原漂移预算内使用更快的清场。这是针对本项目的均衡分组启发式，不宣称算法原创或全局最优。

## 实现与采用条件

1. 保留既有两个参考预算候选及其 10% 负载限制，先选出原有较好方案。
2. 按连续相同画面和允许共享的间隔划分片段，主动空档和内容变化不能跨越。空白片段不参与均衡。
3. 每个片段保留已有音符组数，按实际时间计算等分点，再选最近的合法帧边界；每组至少一帧。不是按帧数平均，因此不等长窗口也能处理。
4. 重新按完整展示平台（包含延长至实际切帧前的部分）计算参考 beatLength 和锚点。
5. 仅在内部总过渡时长相对已选方案再降低至少 20% 时采用，否则保留原方案。随后共用原有 Timeline、音符生成、参考 BPM 和漂移检查。

组数及每组画面完全相同，因此音符数不变。没有添加编译器调用或导入设置；没有提高既有 4900 ms 参考上限、SV 上限或漂移限额，也没有改变帧起止时间。新的重绘边界可能位于同一静止片段内的其他帧，但画面内容不变。

## 可复现对照

24 行、两列、滚速 27、每帧 50 ms、开启长条，静止片段后接 20 帧左右交替动画。下表“总窗口”是模型计算的首尾及内部进退场时间并集，不是实机录像中的残影时长。

| 静止帧数 | 静止片段分组（旧 → 新） | 参考 beatLength（旧 → 新） | 总窗口（旧 → 新） | 音符 |
| ---: | --- | --- | --- | ---: |
| 60 | 29+29+2 → 20+20+20 | 1292.351 → 1874.622 ms | 5.682667 → 3.917590 ms，约 -31.1% | 23 → 23 |
| 80 | 37+37+6 → 27+26+27 | 1012.735 → 1388.163 ms | 7.251650 → 5.290445 ms，约 -27.0% | 23 → 23 |

关闭长条仍使用相同分组与几何，以上案例各自保持 552 个短音符。包含 30/70 ms 不等长窗口的回归确认按时间均衡；旧实现最大组与最小组相差 1400 ms，新方案差值小于 100 ms。

## 验证与负对照

- 新增回归先在旧实现得到 5 处失败，再验证实现。命令：`.build-env/Scripts/python.exe -m unittest discover -s tests -p test_balanced_reuse.py -v`。
- 272 组合成差分：256 组固定窗口与 16 组视频入口，覆盖两端、3/24 行、滚速 27/40、长条开关、静止与动态长度、不等长时间窗口及上下留白。52 组改善（固定窗口 44，视频入口 8），其余谱面不变；所有案例音符数不变、总过渡不增加。stable 共 136 组 `.osu` 逐字节不变。
- 独立解析序列化 `.osu` 并用 lazer 分段 float32 积分，核对头尾底边位置、未来判定时间以及完整复用平台的半内部像素漂移限额。附加回归覆盖 1/18 列、1/128 行与滚速 1/40；这不是对 >10K 原版客户端舞台限制的豁免。
- 主动空档及原本空白帧在独立几何积分中仍为空白；纯静态单组不新增重绘；低于 20% 收益的片段、手动清场和 stable 均保留原策略。
- 视频入口对照覆盖 60/120/480/1000 Hz。此次样例的最坏相位评分没有退化，但也不总是改善：60 静帧案例在 1000 Hz 仍为 22 → 22，尽管总窗口已缩短。不能把总窗口缩短推断为所有显示相位都同等获益。

过程脚本与数据位于忽略目录 `build/compare_balanced_reuse.py`、`build/balanced-reuse-comparison.json`。全部使用合成图案，没有读取或上传个人媒体。

## 使用方式与边界

使用新版 EXE 重新打开旧 lazer 项目并导出，即可重新经过核心均衡流程；原帧窗口和音轨不变，不需要为本项优化重新导入视频。它与前两轮“只有重新导入才会移动视频窗口”的排帧改动不同。stable 保留原算法，不宣称本轮提升了 stable 实机效果。

未控制游戏窗口，未修改客户端或显示器设置。模型窗口变短不等于已验证消除 GPU/Miss 淡出、Auto 频闪、呈现相位误差或显示器拖影。关于尚未实现的去连续命中、自动测相位和物理显示方案，见 [残影创新方向](ghost-innovation-options.md)。

本轮交付验收：完整 220 项测试通过，按 `build_desktop.ps1` 重建 EXE；五个包内项目模块与当前源码一致，内置 FFmpeg 保留。测试、构建及核对记录分别为 `build/full-tests-balanced-reuse.log`、`build/desktop-balanced-reuse.log`、`build/package-balanced-reuse-verified.json`。十个皮肤包未改动。
