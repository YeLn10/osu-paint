# 时间、位置与自动排帧

[架构](architecture.md) · [皮肤几何](skin.md) · [研究索引](research/README.md)

这是当前编译器的数值约束。改时间、位置、SV、长条或视频排帧前阅读本文，并用两客户端各自规则重新解析、积分序列化 `.osu`；预览正确不能代替序列化验证。

## 共同模型

`Timeline` 对分段速度积分，并反解目标位置对应的判定时间。滚速必须与游戏一致，行数只决定格子高度。legacy 音符按底边锚定：H 行中第 row 行底边为 `(row + 1) / H`，贴图向上延伸 `1 / H`；扣除整个复用画面的累计漂移和约 `1 / 768` 底部余量，使展示结束时头部判定时间仍在未来。顶部按舞台裁剪。

长条仅合并同帧同列连续亮格，下方为头、上方为尾，不跨空格或不同画面；相邻相同画面可在漂移预算内复用音符，保留主动空档。全空白帧保留窗口和控制点，可见漂移为 0，不参与参考 beatLength 的漂移限速。

| 计划字段 | 含义 |
| --- | --- |
| `transition_ms` | 均分、视频排帧及空档分组的预算。 |
| `sweep_ms` | 计划中最大实际进出场时长，复用组只计首次进场，不把累计展示算作进场。 |
| `sweep_start_ms` → 下一帧 `start_ms` | 相邻画面的实际过渡区间。 |
| `base_beat_length_ms` | 实际参考值，桌面与 HTML 积分须读取此字段。 |

极速校验先拒绝重叠窗口，再完成复用、参考 BPM 与端点优化，逐一检查实际推进是否放得进间隔。压缩清场仅延长静置，不改帧起止或音轨。非极速共用推进使用用户的 `transition_ms`，余量延长静置；间隔大于两倍预算时保留独立退场、空场和进场。

## 客户端差异

| 项目 | lazer | stable |
| --- | --- | --- |
| 时间与积分 | 小数时间、分段 float32 距离 | 整数头尾和 MovementY 端点；窗口向内取整 |
| 时间范围 | `11485 / scrollSpeed × 480 / 402` | `480 × 600 / (21 × scrollSpeed)` |
| 参考 beatLength | 普通模式 500 ms；极速按漂移预算选 500–4900 ms | 固定 500 ms（120 BPM） |
| 红线统计 | 使用 lazer 分组与参考规则 | 精确 double 分组，以 ULP 区分独特值；序列化 17 位有效数字 |
| 慢段边界 | beatLength 6–60000 ms，SV 0.01–10 | 慢 beatLength 约 1,000,000 ms，不套用 lazer 红线范围 |

stable 的参考统计终点取最后序列化物件的结束，不能改成最大尾时间；更不能将 lazer 小数结果简单四舍五入。版本依据见 [stable 时间证据](research/stable-timing.md)。

## lazer 清场与复用

全高清场距离 `S = 1 + 2 / 768`，覆盖底边偏移并留舍入余量；极速时间和推进速度共享这个常量。

极速根据整幅复用画面（含延长至实际切帧前的展示部分）的漂移预算选择参考 beatLength，预算不足时保留 500 ms。优化复用时依次考虑：

1. 原分组，以及最多两个重分组候选：4900 ms 参考预算、原参考的两倍（不超过 4900 ms）。候选须将内部总过渡至少减少 20%，组数和音符数各最多增加 10%；所有负载限制均与原计划比较，选合格候选中内部过渡最短者。
2. 在已选组数下，按时间均衡各段连续相同画面的复用组。取最接近等时间分点的合法边界，不跨内容变化或主动空档；仅当内部总过渡再缩短至少 20% 时采用。

均衡不增加音符、组数或一次核心编译，不改原帧窗口；参考、锚点、音符和漂移重新计算。首尾进退场不计收益，纯静态序列不会为缩短首尾反复重绘。机制与对照见 [复用优化](research/merged-transition-optimization.md)、[均衡复用](research/balanced-reuse-optimization.md)。

极速还按实际亮格缩短行程。旧图最上亮行 t、新图最下亮行 b，共用行程为 `max(S - t/H, S - (H-1-b)/H)`；空图不约束相应一侧，两侧都空则保留 S。独立退场只看旧顶部，进场只看新底部，时长按行程与 S 的比值压缩。速度上限和安全余量不变，预留一至两倍预算的间隔也按同一极速速度推进。非极速和 stable 不用此压缩。

## stable 清场与底边

保守排帧预算为 H+1 ms。极速仅为实际短音符或长条头尾所在的 N 个不同端点行分配整数时刻，清场需 N+1 ms；空行和长条内部不占时刻，几何跨度保持不变。独立进场可用 1 ms，共用切帧仍在原下一帧起点结束，余量用于静置；非极速保持用户时长。

画面推进与 stable 皮肤的固定底部白色遮挡配套，`bottom_mask_fraction = 1 / 480`，行程为：

```text
max(1 - 1/480 + 1/768 + 1e-6, 1 + 1/768 - 0.5/H)
```

1–128 行视频略微重叠画面，避免移动白缝；极高文字画布仍须在最后行端点后正向移动。离场音符上边缘落在遮挡内，保留 float32 余量；头尾时刻、行高和判定余量不变，漂移上限同时检查实际清场开始。

Tk / HTML 按计划遮挡比例裁剪，旧计划缺少字段则不添加。连续预览不模拟 stable 整数裁剪、头部生命周期或 GPU；原生变换与残余底边反例见 [白缝记录](research/stable-white-seam.md)。

## 慢控制点合并

两端极速在建立 `Timeline` 与生成音符之前使用 `_compact_slow_points`。只合并连续、SV 为 0.01 且 beatLength 大于参考值的慢段，合并跨度不超过首段参考 BPM 前导时长的一半。

保留参考锚点和全部进退场/空档边界，保留的慢红线仍互异。合并后重新积分、求头尾位置与漂移，不沿用旧几何；参考预算和复用分组仍保守估算，最后按各客户端规则验证参考 BPM。非极速不合并。减少控制点不等于证明客户端帧率提升或时钟定格修复。

## 视频采样与刷新窗口

按视频时间戳采样，支持可变帧率；以实际刷新频率和向上取整的分频数直接推导边界，不累计取整、不提高请求 FPS。保留请求行数，stable 默认 12 行、lazer 默认 24 行。画面与 Ogg 保持共同开始时间及源音画延迟，排帧只调整画面。

stable 首边界 ceil，其余按独立有理刷新周期 floor；首帧不足 1 ms 展示则拒绝，音轨原始小数起点保留。清场超过一个显示刷新间隔时警告，不套用 lazer 的小数窗口假设。

### 候选顺序与采用条件

固定相位评分用有理刷新周期的端点扫描与命中位图，避免浮点取模制造伪重叠。除 stable 长清场分支外，基线加候选最多四次核心编译：

1. **基线与重绘组候选**：lazer 保留按采样序号推进的三角排帧基线，再按实际重绘组（含静态内容因漂移重绘）每 64 次走完余量后折返。stable 由核心给出整数清场时长，在前一次名义刷新后至本次刷新前平滑移动并向下取整。
2. **紧缩候选**：最多再编译一次。lazer 按实际 `sweep_ms` 计算保护余量；stable 将连续偏移一次取整后钳制到安全整数范围。重编译后实际推进仍须在前一次名义刷新后开始。最坏固定相位命中须严格改善，音符数和内部总过渡不增加，才替换当前方案。
3. **快速折返候选**：按 9/64、7/64、5/64、3/64 顺序检查，只编译第一个通过排帧约束且时间变化的候选。编译后无收益或越界即停止搜索。最长连续命中须严格减少，最坏总命中、音符数、内部总过渡不增加，相邻帧开始间隔相对名义周期偏差不超过 1 ms。lazer 使用实际余量，stable 沿用已选余量策略。

所有新候选重新检查实际推进边界。展示时间、整数余量不足或无收益则保留已选方案，不改变核心速度上限和端点算法。各次微调小于一个刷新周期；请求/实际参数及对齐元数据保存在项目和报告中，界面不展示内部转换说明，也不提供相位输入。初始收益和续优化条件见 [相位优化](research/ghost-phase-optimization.md)、[连续命中优化](research/ghost-streak-optimization.md)。

### stable 长清场补充候选

清场大于半个刷新周期但小于一个周期，且内容周期减去两个刷新周期后还能容纳原预算和 1 ms 展示时，最多额外编译两个候选（连基线最多六次）：

1. 按实际重绘组在接近一个完整刷新周期内折返。
2. 仅在上一个宽候选已采纳后，按整数帧间隔的可用速度折返：每次真正重绘向可用范围一端推进，下一开始限定于前一时刻加 `ceil(名义周期 - 1)` 到 `floor(名义周期 + 1)` 之间；实际提前量不再变化时反向，同一音符组保留相位目标。

两者让画面最多提前不到一个刷新周期，允许跨过前一次名义刷新，但必须在前两次名义刷新之后开始。不能沿用窄余量方案“前一次刷新仍是完整旧图”的保证。首尾时间、FPS 和音轨不变，帧间隔偏差不超过 1 ms。

每个候选相对当前方案必须同时严格减少最坏总命中和最长连续命中，且不增加音符或内部总过渡，否则回退。清场本身未缩短，个别相位仍可能变差；见 [扫屏复核](research/stable-sweep-optimization.md) 和 [整数节奏优化](research/stable-cadence-optimization.md)。

## 验证边界

序列化回归检查进入前不可见、退出后无残留、长条头尾、参考 BPM 和漂移。修改视频候选还需验证原帧时间/音轨约束、负载、收益门槛及实际刷新边界；保留任意相位采到过渡的反例。

Hz 不能确定实际显示相位；模型里的清场缩短、命中分散或连续几何正确，均不能证明 GPU 实机零残影、判定淡出消失或时钟定格修复。实机结论以对应版本的独立证据为准。
