# osu-paint

把 `#` / `.` 文本像素图或视频变成 osu!lazer / stable mania 音符图案、多帧动画。两个工具现已合并为同一个应用，视频的音乐会打包进谱面。在指定毫秒区间展示，通过快速滚动进场、切帧和退场。展示阶段是**近似停止**，不是精确零速。

## 桌面端（Windows）

直接双击 **`dist/osu-paint.exe`** 即可打开独立桌面窗口，无需安装 Python，也不会弹出命令行窗口。可以将这个 EXE 单独复制到其他目录使用；它不依赖旁边的示例文件或源码。

- **工作区**：左侧画布与帧列表，右侧预览与时间参数；顶部打开、保存或导入视频，底部选择目录并导出。
- **客户端**：手绘项目在顶部切换 `lazer` / `stable`；视频在导入窗口选择，导入后顶部只显示目标，换端需重新导入。两端共用界面，时间模型与皮肤各自独立。
- **绘制**：左键点按或拖动绘制，右键擦除；“新建”设置 1–18 列和行数，“编辑文本”粘贴 `#` / `.` 图案，滚动浏览多帧，取消或按 Esc 不应用修改。
- **动画帧**：新增空白帧、复制、删除或切换；列表显示亮格数，底部状态显示合并后的实际音符数。切帧、绘制和逐帧时间编辑只更新当前列表项，不重建整段视频的列表。
- **时间**：均分模式分配总时长；自由模式逐帧设置起止时间，支持空档，不允许重叠。切换模式保留原设置。
- **极速清场**：默认开启，自动切帧时长显示到 0.001 ms，计算精度不变；关闭后恢复可编辑的手动值。
- **合并长条**：默认开启，仅合并同帧、同列的相邻亮格，不跨空格。旧项目保留原开关；缺少此字段时使用短音符。
- **预览**：播放、暂停、拖动时间轴；“定位”回到当前帧。视频音轨同步播放，位置模拟不等于实机渲染。客户端限制按当前画布提示，完整参数与漂移估计见“说明”。
- **保存**：JSON 保留图案、时间、参数和视频音轨；TXT 仅保存图案。新建、打开或关闭前会确认未保存修改。
- **导出**：点击“导出 .osz”，完成后“打开结果”，分别导入谱面与对应比例的 `.osk`。皮肤匹配本次画布行数；覆盖前确认，不删除其他文件。导出使用点击时的快照，可继续编辑。

JSON 项目可以保存尚未绘制完成的空白帧，重新打开后继续编辑；普通图案仍需每帧至少有一个音符才能导出谱面。另存 TXT 只导出图案，不会将尚未保存的项目参数标记为已保存；保存 JSON 后才清除未保存状态。

预览模拟连续的音符位置，不是游戏渲染。桌面预览可同步播放已导入的音乐；HTML 预览仍无声。生成器和 CLI 使用同一套逻辑，具体限制及游戏设置见下文。

### 视频与音乐导入

1. 点击右上角 **“导入视频”**，选择本地 MP4、MKV、WebM、AVI、MOV、WMV 等视频（实际支持情况取决于内置 FFmpeg 的解码器）。
2. 先选择 **目标客户端 stable / lazer**，再设置 **帧率 / FPS**（每秒帧数，可用 `12.5`、`29.97` 等小数）、**列数**（1–18）、**行数**（1–128）。默认 `10 FPS`、10 列；lazer 默认 24 行，stable 默认 12 行。切换客户端只调整尚未编辑的默认行数，手动填写的行数保留；取消或失败不会改变原项目客户端。
3. 设置 **音画开始 / ms**，默认 `2000`。它是共同的谱面时间偏移，不是从源视频中裁剪的起点；音轨前会补相应静音。
4. 调整黑白阈值、亮度、对比度、亮暗反转和缩放方式；填写 **“预览帧”**，点击 **“刷新预览”**，对照右侧原画面和转换结果。序号从 1 开始，按当前 FPS 抽帧；例如 10 FPS 的第 11 帧对应源视频 1000 ms。修改参数后再次点击预览。选帧只影响预览，完整导入仍从视频开头开始。
5. 核对 **屏幕刷新率 / Hz** 和与游戏相同的滚速，按需勾选 **合并长条**，再点击 **“开始导入”**。预览与转换均在后台运行，可取消；完成后可以逐帧编辑、保存 JSON 项目，或导出 `.osz`。

**分辨率是音符画布的列数 × 行数，不是原视频的 1920 × 1080 等编码尺寸。** 可生成 1–18K 谱面；原版 lazer 的 >10K 有下文所述的拆分和少列限制。默认拉伸，灰度 ≥128 的像素成为黑色音符，其余留空；可以选择等比留边或居中裁剪。不会把原视频作为背景视频附加到谱面，也不保留彩色。列数很低时无法恢复已经被缩小丢失的细节。

| 转换参数 | 用法 |
| --- | --- |
| 黑白阈值 0–255 | 降低可保留较暗轮廓，提高可减少背景噪点；默认 128。 |
| 亮度 -255–255 | 调整整体明暗，默认 0。 |
| 对比度 >0–5 | 以灰度 128 为中心调整差异，默认 1；在缩小画面后、阈值判断前应用。 |
| 亮暗反转 | 暗部生成音符，适合白底黑色轮廓。 |
| 缩放方式 | 拉伸填满、等比缩小并补黑边、等比放大并居中裁剪；预览和导入使用同一流程。反转也会作用于黑边。 |

- **画音同步**：按源视频时间戳采样，支持可变帧率视频；从开始时间与索引直接计算各边界，不累计取整。应用自动将换帧放在预定刷新之间，音轨保持共同开始偏移。黑场保留其时间，不删帧、不插假音符。视频末尾以解码器提供或推断的帧时长为准，再对齐到完整采样周期；缺少准确时长信息的文件可能有尾帧估计误差。
- **音乐**：提取第一个音轨，转为 Ogg，并保留源文件中音画流的相对延迟。导出的 `.osu` 使用 `AudioFilename: audio.ogg`，`.osz` 包含该音频；无音轨的视频改用静音，并在界面提示。音轨转换失败会使整次导入失败，不会悄悄丢失音乐。
- **时间模式**：导入后自动启用自由模式和极速清场。长视频使用互异慢红线及短暂参考段，避免大量切帧改变参考 BPM。手动调整帧时间只改变画面，不会自动重定时已经提取的音轨；要一起调整 FPS、分辨率或共同开始时间，请重新导入。
- **项目保存**：视频项目使用 JSON v2，内嵌音轨、转换后的帧和转换参数；关闭程序、移动项目或删除原视频后仍可打开并导出。更改转换参数需要重新选择原视频。仅记录原文件名，不记录视频的绝对路径。项目保存目标客户端；已有 stable / lazer 项目按原目标打开，未标记项目默认 lazer。保留画面、时间和音轨，只忽略过时的游戏 FPS 与手动相位标记。TXT 不保存音轨、视频设置或逐帧时间，不能代替完整项目。
- **资源限制**：`0 < FPS ≤ 60`；每次最多 20,000 帧，总采样像素不超过 2,000,000（帧数 × 列数 × 行数）。超限会拒绝导入，而不是截断视频。滚速过低、无法在一个采样周期内安排展示与切帧时也会提示降低 FPS。较高的 FPS / 分辨率会明显增加音符数、导出大小和游戏负担。
- **预览与音乐**：桌面端点击“播放”会从进度条位置同步播放项目内的音轨，暂停同时停止音乐；拖动进度条或“回到当前帧”会暂停，再次播放从新位置继续。画面跟随音频播放进度，音轨结束后剩余画面继续无声播放。编辑、切换项目或关闭窗口会停止音乐；没有音轨的项目照常无声预览。音频设备不可用时显示错误并继续画面预览。HTML 预览仍无声。游戏内请使用该次导出配套的 Pixel Film 皮肤、相同滚速与 No Fail；全黑视频无法生成有效音符谱面。

### 实际刷新率排帧

视频导入填写 **屏幕刷新率 / Hz** 和 **音画开始 / ms**，应用自动排帧。支持 60、120、165 Hz 及 `59.94`、`60000/1001` 等；默认 60 是输入初值，**不会自动检测显示器**。填写游戏实际使用的刷新率，截图中的游戏 FPS 不能替代屏幕 Hz。

- lazer 保留原来的缓慢分散排帧，并尝试按实际重绘组推进，避免重复画面恰好与排帧周期重合。只有最坏相位命中更少、音符数和总过渡时长不增加时才采用；音轨不移动，也不需要手动调相位。
- stable 保留整数毫秒边界，短清场有余量时尝试在相邻名义刷新之间分散，取整后仍须保留至少 1 ms 展示；无收益或清场过长时保留原排帧。最坏排帧预算仍为行数 + 1 ms，过高 FPS 会拒绝，不会静默删行。
- 新项目保存自动排帧信息；导出附带简短的 **`播放设置.txt`**。改滚速、帧时间、时间模式或画布尺寸后撤销失效标记，需要重新导入才能重新排帧。旧项目保留画面时间与音轨，旧手动相位标记不再作为可调参数。
- Hz 只确定刷新间隔，开始时间只确定谱面中的起点。它们不能确定游戏线程与显示器实际采样时刻；**原版客户端不能据此保证零残影和零下落过渡**。已保留 60、120、165 Hz 的任意相位反例测试，详细原理放在 [刷新约束文档](docs/research/render-phase-constraints.md)，不要求玩家手动校准。

2026-10-07 的合成相位对照：60 Hz 下，lazer 周期性重复画面的最坏命中从 16/16 降至 2/16；stable 整列长条从 64/64 降至 15/64。**这是减少连续命中的排帧优化，不是缩短总过渡或实机消除残影；stable 的 165 Hz 样例没有改善，自动保留原方案。** 详细条件见 [残影排帧验证](docs/research/ghost-phase-optimization.md)。使用本项优化需重新导入原视频；仅重新导出旧 JSON 不会改变原帧时间。

全高画面的清场距离已从旧版的 1.1 屏缩为一屏加 2 个内部像素余量。lazer 极速模式还会按旧画面的顶部、新画面的底部一起检查，只省掉上下留白允许省去的行程，不提高既有滚动速度上限；全高画面及手动切帧不套用留白压缩。打开旧视频项目重新导出即可生效，已保存的自由模式帧时间和音轨保持不变，已有 `.osz` 需要重新导出并导入游戏。这是模型中的过渡窗口缩短，不是实机零闪影保证。

默认 10 FPS 每 100 ms 才有新画面，极速清场只缩短过渡，不会补出运动细节。想提高运动流畅度可从 20 或 30 FPS 试起，但较高 FPS 会增加音符数和游戏负担；低帧率源视频也不会因此生成真实的新细节。程序不会向上提高填写的 FPS；必要时向下换算，因此可能稍降流畅度。分散换帧不能保证所有显示时序都改善，也不能消除视频自身的明暗闪动。**使用新排帧策略需要重新导入原视频，再导出并重新导入游戏；旧项目直接导出会保留旧帧时间。**

lazer 也复用相邻相同画面的音符，避免静态内容每个采样周期都重新进出场；保留主动空档。极速模式只在总切帧窗口至少减少 20%、额外音符和画面组各不超过 10% 时，适度拆分长静态组，避免它拖慢全片；最大提速方案超过负载限制时，还会比较一个较温和的方案，而不是直接放弃优化。纯静态序列不因此反复重绘。完全不含音符的空画面不再参与漂移限速，避免片头、片尾或中间空白把整片切帧拖慢；这一项修复可打开旧 JSON 项目重新导出生效，帧时间与音轨不变。刷新率修正消除了已复现的取整时钟错位，不能据此认定所有周期性残影都来自同一个原因。

### 连续亮格转长条

**合并长条** 将每列每段相邻亮格转换为一个 mania 长条：下方为头、上方为尾，不跨空格或不同画面合并。桌面预览、HTML 预览和 `.osu` 导出共用同一模型。关闭后仍为普通短音符。配套皮肤的头、身体和尾部均为不透明纯黑，长条中间与头尾同色。

短音符及长条头尾的纯黑贴图也已绕过 lazer 纹理图集，减少边缘透明采样造成的白／灰细线。**需要重新导入该次导出目录中的新版 `.osk` 并重新载入皮肤；只更新程序或 `.osz` 不会更新游戏里的旧皮肤。** 皮肤修复无需重新抽视频；旧项目想改用长条，需手动勾选后重新导出。

使用向下滚动、与生成时相同的滚速和 No Fail。全屏位置模型需要该次导出配套的 Pixel Film 皮肤；其他皮肤的判定位置和音符尺寸会影响画面。程序不会修改游戏或系统配置。

```powershell
python osu_paint.py "D:\Videos\clip.mp4" --video --refresh-hz 60000/1001 --fps 10 --width 9 --height 24 --start-ms 2000 --merge-holds --output output/video
```

CLI 视频也自动排帧，未填写刷新率时按 60 Hz；手动相位参数已删除。极速清场会尽量保持上一画面，到下一画面到位前再快速切换；短画面提速更多，长时间复用画面会限制提速以控制漂移。旧项目打开后重新导出即可采用这项优化，不需要重抽视频或移动音轨；已有 `.osz` 不会自动更新，需要重新导出并导入游戏。验证依据及实机限制见 [刷新约束与验证记录](docs/research/render-phase-constraints.md)。

### Pixel Film 全屏皮肤（1–18K）

导出时自动生成 **16:10、16:9、4:3、2560×1080、3440×1440** 五个版本，均支持 1–18K。lazer 默认 `pixel-film.osk`（stable 为 `pixel-film-stable.osk`） 对应用户屏幕 **3072×1920（16:10）**；同一比例也适用于其他分辨率。请导入该次导出目录中的皮肤，音符高度会匹配实际画布行数。根目录 [pixel-film.osk](pixel-film.osk) 等交付包默认对应 24 行。

白色轨道上显示纯黑短音符和长条，判定位置在底边，列间距与边框均隐藏。lazer 列宽按屏幕比例均分，1–10K 保留真实键数并铺满横向；游戏舞台缩放使用默认值。纵向覆盖所有行，底部保留约 1 个内部像素（3072×1920 屏幕约 2.5 像素）的判定余量，加上微小的展示漂移。已有同名皮肤需要覆盖并重新载入，旧谱面需要重新导出。

stable 使用独立皮肤合并 1–18K 舞台，不丢奇数余列；每列最多 100，低键数可能不能铺满全宽。两端皮肤不要混用。

目标原版 lazer `2026.921.0` 的转换器对 >10K 强制双舞台，并会将 11/13/15/17K 转为少一列的偶数键数。单独导入皮肤不能解除这个客户端限制。各比例的文件名、构建方式、配置依据和验证边界见 [皮肤说明](docs/skin.md)。

项目维护约束见 [AGENTS.md](AGENTS.md)，模块与数据流见 [架构文档](docs/architecture.md)。

### 自由模式与参数含义

可打开 `examples/free.json` 体验三帧时间表：2000–2500 ms、3000–4500 ms、4501–6000 ms。首帧在 2500 ms 开始退场，第二帧在 3000 ms 完整到位；中间留出空档。第三帧与第二帧间隔很短，会共用一次推进。

“开始 / 结束”指**完整图案的展示区间**，进场在开始之前，退场从结束时刻开始。不能将有限速度的滚动设成零时间瞬移。每帧需要结束 > 开始，按列表顺序排列，相邻两帧的间隔至少为保守排帧预算；间隔超过两倍预算时，分别退场和进场，中间保持空场。新增或复制帧会放在当前帧之后，不会自动挪动其他帧的时间。

| 参数 | 实际影响 |
| --- | --- |
| 切帧时长 | 一次快速推进一个完整舞台加 2 个内部像素余量所花的时间；越短越快，越长越容易看见下落。均分模式先从总时间扣除切帧时间；自由模式保持填写的展示时间，检查间隔是否足够。 |
| 极速清场 | 覆盖手动切帧值，自动接近合法速度上限。lazer 滚速 27 的保守预算约 0.612 ms，可根据漂移预算进一步压缩；stable 保守预算为行数 + 1 ms，实际按不同头尾端点行数 + 1 ms 清场（例如 24 行整列长条为 3 ms，全行短音符仍为 25 ms）。界面底部和报告显示实际值。短间隔共用推进，多余时间延长静置，不改变保存的帧起止或音轨。关闭极速后，手动值就是实际清场时长，不再被整个帧间间隔覆盖。 |
| 游戏滚速 | 必须与游戏内相同（stable 为 1–40 的整数，lazer 可用小数），决定滚动时间如何换算为舞台上的位置和速度。不是动画 FPS，也不是 BPM；调大不会改变自由模式填写的展示时间。生成器会重新计算音符位置与变速点，只改游戏内滚速而不重新生成会使图案变形或错位。 |

旧版默认 12 ms 的退场仍会被显示器采到。极速清场改的是实际导出的红线、绿线和音符时间；在 lazer 默认滚速 27 的位置模型中，旧图案在结束后 1 ms 内已越过整个舞台及判定线下方区域。新预览不会通过提前隐藏音符制造“已清场”的假象，但不模拟游戏的皮肤、判定与 Miss 淡出。有限速度仍可能被某一次刷新采到，不能承诺绝对零残影；自定义皮肤或不同客户端版本仍需实测。

点击界面的“参数说明”也能查看这些规则。JSON 项目保存全部编辑参数；`report.json` 是导出检查报告，不是可打开的项目文件。

- `output/heart/report.json`：时间点、音符位置、参考 BPM、预测漂移。

## 输入和时间含义

每行等宽，支持 1–18 列，每列对应一个按键列；从上往下书写图案，`#` 表示普通音符，`.` 表示空位。例如：

```text
.##.##.
#######
#######
.#####.
..###..
...#...
```

程序按 lazer 贴图底边定位，H 行底边为 `(row + 1) / H`，扣除展示漂移与约 1 个内部像素的判定余量。配套皮肤让每个黑块高度为屏幕高度的 `1 / H`，列宽按屏幕比例均分。黑块的宽高由键数与行数决定，通常是矩形。

`--start-ms 2000 --end-ms 4000` 表示：

| 时间 | 行为 |
| --- | --- |
| 1988–2000 ms | 快速进场 |
| 2000–4000 ms | 完整展示，极低速漂移 |
| 4000–4012 ms | 快速退场 |

使用 `--transition-ms` 修改进场、退场各自的时间，默认 12 ms。进场前必须留出至少 100 ms 的正常 BPM 段；程序会检查参考 BPM 是否仍为 120。不合法的时长或改变参考 BPM 的组合会报错。

音符的**判定时间位于退场段**。这不是错误：要使音符留在判定线上方，必须根据滚动距离反解未来的判定时间，不能将展示起点直接当成音符时间。

## 多帧动画

把多个同尺寸图案写入一个文本文件，以独立的 `---` 行分隔。每帧至少包含一个 `#`。例如：

```text
#..
.#.
..#
---
..#
.#.
#..
```

已有三帧心形放大示例：

```powershell
python osu_paint.py examples/pulse.txt --start-ms 2000 --end-ms 5000 --output output/pulse
```

所有帧平分给定时间范围，先扣除帧间的换帧时间；外侧进场、退场仍在时间范围之外。上例中：

| 时间 | 行为 |
| --- | --- |
| 1988–2000 ms | 第一帧进场 |
| 2000–2992 ms | 第一帧展示 |
| 2992–3004 ms | 第一帧退场，同时第二帧进场 |
| 3004–3996 ms | 第二帧展示 |
| 3996–4008 ms | 第二次切帧 |
| 4008–5000 ms | 第三帧展示 |
| 5000–5012 ms | 最后一帧退场 |

`report.json` 的 `frames` 列出每帧的实际展示时间和漂移；顶层漂移值表示各帧中的最大值。预览随播放切换当前文本图案与帧号。

慢速红线的 beatLength 在整段动画中保持互异。相同快速红线累计时长也会影响参考 BPM；如果帧数太多导致参考 BPM 改变，程序会报错，需要增加 `--start-ms` 留出更长的开场，或缩短合法范围内的换帧时间。时间范围必须严格大于所有帧间切换时间之和。

## 在 lazer 中查看

1. 导入 `pattern.osz`，选择生成的 `SV Pattern` 难度。
2. 导入并选择该次导出中匹配游戏窗口比例的 Pixel Film `.osk`，使用向下滚动，将 mania 滚速设为 **27**。也可以生成时指定 `--scroll-speed`，并同步游戏设置。
3. 开启 No Fail；不要启用恒速滚动、改变列数、随机排列、镜像或速度类 MOD。播放时不要跳过开头。

原版 mania 的坐标模型按 Pixel Film 全高舞台计算：内部高度 768、皮肤判定位置 480，对应 `TimeRange = 11485 / ScrollSpeed × 480 / 402`。其他皮肤、舞台缩放或 MOD 需要重新校准；原版 lazer 的 >10K 仍按上述限制拆分。

两秒示例的理论漂移约 **0.252 像素 / 768 内部像素高度**，实际屏幕像素按显示高度缩放。预览只是位置模型，不模拟游戏的判定、淡入淡出和物件生命周期。12 ms 的快段也可能被显示器采到，不能保证完全无过渡帧。

### 画面定格但音乐继续

目标 lazer `2026.921.0` 存在一种已复现的客户端时钟定格：音符区域追赶音频时触发 500 ms 时间差保护，之后持续拒绝更新，但音频仍然播放。日志会出现 `Ignoring likely invalid time value provided by BASS during gameplay`，连续异常最多记录 10 次；不能因后面没有报错就认为已恢复。

**不再推荐用 Autoplay（AT）作为观看方案**：安装版本的 DLL 对照证明它能绕过这条时钟保护，但随后用户实机反馈 AT 会造成强烈频闪。该对照只能解释定格机制，不能证明视觉效果可用。只开 No Fail 不会避开此保护；Cinema（CN）会隐藏用于显示图案的音符区域，同样不适用。当前尚无经过实机确认、同时解决定格与频闪的方案，不应为此盲目调整 SV 或重新导出。诊断依据、实机反馈与验证边界见 [客户端时钟定格记录](docs/research/lazer-clock-freeze.md)。

## 原理和验证

当前 lazer 的绿线 SV 被限制在 0.01–10，红线 beatLength 在 6–60000 ms。程序组合红线和绿线，并积分实际倍率来布置音符。慢段先按 50 ms 分配不同的合法 beatLength，避免长慢段变成参考 BPM；极速模式再合并冗余慢段，合并跨度不超过参考 BPM 前导时长的一半，并保留参考锚点与所有进退场。每条红线后都补同时间绿线。详细证据见 [调查报告](docs/research/mania-sv-animation.md)。

```powershell
python -m unittest discover -s tests -v
```

桌面交互测试使用真实 Tk 控件，需要可用的图形桌面环境；覆盖绘制/擦除、多帧、自由模式逐帧时间、JSON 保存恢复、文本读写与编辑窗口按钮布局、参数验证、播放进度、覆盖确认、后台导出及关闭保护。导出级测试包含自由时间表、空档、合法速度边界、120 帧切换及完整舞台清场。

测试重新解析导出的 `.osu`，独立积分并包含 lazer 的分段 float32 舍入，检查图案方向、列号、起点坐标、展示漂移、进出场、速度上下界、参考 BPM、输入错误和 `.osz` 内容。多帧测试还检查相邻帧串入、120 帧时的参考 BPM；安装了 Node.js 时，会额外检查单帧和多帧预览的 JavaScript 语法。

**目前完成源码核查与自动化数据验证，尚未完成 osu!lazer 的游戏内显示验收。** 程序支持文字图案、视频、逐帧时间、视频音乐和连续亮格转长条，不修改已有谱面。

### 2026-10-06 切帧优化

两端极速模式还会减少冗余近静止控制点，让导出的谱面更轻；例如静止 2 秒的合成画面，慢控制点从 40 个减到 3 个，参考 BPM、音符数和画面时间不变。lazer 不再因为预留切帧间隔较宽而降低极速清场的速度，仍使用既有速度上限；stable 的整数头尾与实际切帧时长不变。控制点变少不等于已证明客户端帧率提高、闪影消失或时钟定格修复。

打开旧 JSON 项目、确认客户端和“极速清场”后重新导出即可使用本次优化，无需重新抽帧；切换客户端后若旧窗口不满足目标的时间预算，则需重新排帧。stable 稀疏画面/长条不再为未使用的端点行浪费清场时刻；lazer 对长静态片段采用有收益且限负载的复用策略。详细对照见 [验证记录](docs/research/merged-transition-optimization.md)。

这不是 Auto 频闪或 lazer 音乐继续、画面定格的客户端修复，也不保证未知显示相位下零闪屏。观看仍用 NF，不开 Auto。
